# Автоматизированное построение признаков для рекомендательных систем

Экспериментальный проект для автоматизированного построения и оценки исторических признаков в рекомендательных системах на основе датасета MovieLens 1M.

В проекте исследуется, насколько исторические признаки взаимодействий пользователей с объектами улучшают качество предсказания оценок, а также как различные группы признаков влияют на качество модели, время выполнения и потребление памяти.

## Обзор проекта

В экспериментах используется датасет MovieLens 1M, содержащий **1 000 209 оценок**.

Задача предсказания рейтинга преобразуется в задачу бинарной классификации:

- `1` — оценка пользователя не меньше 4.
- `0` — оценка пользователя меньше 4.

Для предсказания используется классификатор CatBoost.

Сравниваются четыре конфигурации признаков:

1. **Baseline** — базовые признаки пользователей и объектов.
2. **History counts** — признаки, описывающие количество исторических взаимодействий.
3. **Rating statistics** — статистики исторических оценок.
4. **Combined** — комбинация нескольких групп признаков.

Основные цели проекта:

- построить исторические признаки без использования информации из будущего;
- сравнить качество предсказаний при использовании разных групп признаков;
- оценить вычислительную стоимость построения признаков;
- уменьшить время выполнения и потребление памяти;
- проверить эквивалентность оптимизированной реализации построения признаков и эталонной реализации.

## Датасет

В экспериментах используется **MovieLens 1M**.

Датасет содержит оценки фильмов пользователями и временные метки, позволяющие обрабатывать взаимодействия в хронологическом порядке.

Исходные оценки преобразуются в бинарные метки:

\[
y =
\begin{cases}
1, & \text{если оценка} \geq 4,\\
0, & \text{если оценка} < 4.
\end{cases}
\]

Таким образом, задача рассматривается как задача бинарной классификации.

### Временное разделение данных

Данные разделяются на три последовательные части:

- **Обучающая выборка:** приблизительно 70% взаимодействий.
- **Валидационная выборка:** приблизительно 20%.
- **Тестовая выборка:** приблизительно 10%.

Взаимодействия упорядочиваются по временным меткам. События с одинаковыми временными метками не разделяются между частями выборки.

Такое разделение позволяет оценивать модель в условиях, приближенных к реальному использованию: модель обучается на прошлых взаимодействиях, а затем проверяется на более поздних.

## Методология

### Конфигурации признаков

В эксперименте сравниваются четыре конфигурации.

| Конфигурация | Описание | Количество признаков |
|---|---|---:|
| Baseline | Базовые признаки пользователей и объектов | 5 |
| History counts | Базовые признаки и исторические счётчики взаимодействий | 17 |
| Rating statistics | Базовые признаки и статистики исторических оценок | 9 |
| Combined | Комбинация построенных групп признаков | 21 |

#### Baseline — базовые признаки

Базовая конфигурация содержит пять признаков, описывающих пользователей и объекты.

Она используется как отправная точка для оценки вклада исторической информации в качество предсказаний.

#### History counts — исторические счётчики

Эта конфигурация включает признаки, отражающие количество ранее наблюдавшихся взаимодействий.

Они позволяют учитывать объём доступной истории пользователя или объекта на момент предсказания.

#### Rating statistics — статистики оценок

Эта конфигурация включает статистические характеристики ранее наблюдавшихся оценок.

Такие признаки позволяют учитывать историческое поведение пользователей и характеристики оценивания объектов, не используя информацию из будущих взаимодействий.

#### Combined — комбинированная конфигурация

Комбинированная конфигурация объединяет признаки из нескольких групп.

Её цель — проверить, позволяет ли совместное использование разных видов исторической информации повысить качество предсказаний.

### Построение исторических признаков

Исторические признаки рассчитываются только на основе взаимодействий, доступных до момента предсказания.

Для временного окна используется интервал:

\[
[t-\Delta, t),
\]

где:

- \(t\) — временная метка предсказываемого взаимодействия;
- \(\Delta\) — продолжительность временного окна;
- нижняя граница интервала включается;
- верхняя граница интервала не включается.

Следовательно, взаимодействие с временной меткой \(t\) не может использоваться при построении признаков для другого взаимодействия с той же временной меткой.

Все взаимодействия с одинаковыми временными метками обрабатываются пакетно. Сначала признаки для всего пакета рассчитываются на основе истории, существовавшей до его обработки. Затем история обновляется.

Это предотвращает взаимное влияние взаимодействий с одинаковыми временными метками при расчёте признаков.

### Протокол онлайн-оценки

Оценка модели проводится в хронологическом порядке с последовательным обновлением исторических данных.

1. Модель обучается на тренировочной выборке.
2. Валидационная выборка используется для выбора модели и ранней остановки обучения.
3. Во время тестирования параметры модели остаются неизменными.
4. По мере поступления новых взаимодействий обновляется состояние исторических данных.
5. Для каждого предсказания используются только сведения, доступные до соответствующего взаимодействия или пакета взаимодействий с одинаковой временной меткой.

Предыдущие взаимодействия из валидационной выборки и уже обработанные тестовые взаимодействия могут использоваться при построении признаков для последующих событий. Предполагается, что оценки предыдущих взаимодействий становятся доступными до формирования следующих предсказаний.

При этом сама модель во время тестирования не переобучается.

Таким образом, необходимо различать обновление исторических данных, используемых для построения признаков, и обновление параметров модели.

## Результаты экспериментов

### Качество предсказаний

В таблице представлены результаты для четырёх конфигураций признаков.

| Конфигурация | Признаки | ROC-AUC на валидации | LogLoss на валидации | ROC-AUC на тесте | LogLoss на тесте |
|---|---:|---:|---:|---:|---:|
| Baseline | 5 | 0.7449 | 0.5969 | 0.7440 | 0.5987 |
| History counts | 17 | 0.7490 | 0.5902 | 0.7466 | 0.5940 |
| Rating statistics | 9 | 0.7812 | 0.5886 | **0.7752** | 0.5964 |
| Combined | 21 | **0.7832** | **0.5832** | 0.7744 | **0.5962** |

### Анализ результатов

**Baseline**

Базовая конфигурация достигает ROC-AUC 0.7440 на тестовой выборке. Этот результат используется как ориентир для оценки вклада исторических признаков.

**History counts**

Добавление исторических счётчиков увеличивает ROC-AUC на тестовой выборке с 0.7440 до 0.7466 и уменьшает LogLoss с 0.5987 до 0.5940.

Это указывает на то, что количество исторических взаимодействий содержит полезную информацию для предсказания оценок.

**Rating statistics**

Конфигурация со статистиками оценок показывает наилучший результат по ROC-AUC на тестовой выборке — **0.7752**.

По сравнению с базовой конфигурацией абсолютный прирост ROC-AUC составляет 0.0312.

Среди рассмотренных вариантов эта конфигурация обеспечивает наилучшее разделение положительных и отрицательных примеров на тестовой выборке.

**Combined**

Комбинированная конфигурация показывает наилучший результат на валидационной выборке: ROC-AUC составляет **0.7832**, а LogLoss — **0.5832**.

На тестовой выборке ROC-AUC равен 0.7744, а LogLoss — 0.5962.

Несмотря на лучшие результаты на валидации, комбинированная конфигурация не достигает максимального тестового ROC-AUC. По этому показателю немного лучше работает конфигурация Rating statistics.

### Интерпретация

Результаты показывают, что статистики исторических оценок содержат значимую для предсказания информацию.

Объединение всех групп признаков улучшает результаты на валидационной выборке, однако в данном эксперименте не обеспечивает наилучший ROC-AUC на тестовой выборке.

Полученные результаты необходимо интерпретировать с осторожностью: эксперимент проведён на одном временном разбиении данных. Поэтому нельзя утверждать, что одна конфигурация будет стабильно превосходить остальные на других датасетах или временных интервалах.

Для проверки устойчивости результатов необходимо провести дополнительные эксперименты с несколькими временными разбиениями.

## Производительность

Для оценки эффективности реализации проведено сравнение времени построения признаков и отслеживаемого пикового потребления памяти Python.

| Метрика | До оптимизации | После оптимизации |
|---|---:|---:|
| Время выполнения | 55.53 с | 10.77 с |
| Отслеживаемое пиковое потребление памяти Python | 1349.48 МиБ | 991.28 МиБ |

### Результаты оптимизации

После оптимизации время выполнения сократилось с 55.53 до 10.77 секунды.

Ускорение составляет приблизительно **5.15 раза**.

Отслеживаемое пиковое потребление памяти Python уменьшилось с 1349.48 до 991.28 МиБ.

Таким образом, оптимизированная реализация позволяет существенно ускорить построение признаков и одновременно уменьшить отслеживаемое потребление памяти.

Следует учитывать, что приведённые значения памяти относятся к использованному механизму измерения Python и не обязательно отражают полное потребление памяти процессом на уровне операционной системы.

## Установка

### Требования

- Python 3;
- pip;
- зависимости, перечисленные в `requirements.txt`.

### Создание виртуального окружения

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Установка зависимостей

```bash
pip install -r requirements.txt
```

## Запуск экспериментов

Запуск основного эксперимента:

```bash
python -m scripts.run_experiment
```

Запуск бенчмарка построения признаков:

```bash
python -m scripts.benchmark_features
```

Проверка эквивалентности реализаций построения признаков:

```bash
python -m scripts.check_feature_equivalence
```

Запуск автоматизированных тестов:

```bash
pytest -q
```

## Тестирование

В проекте предусмотрены автоматизированные тесты для проверки корректности реализации.

На текущий момент тестовый набор включает **21 успешно пройденный тест**.

Проверка эквивалентности предназначена для подтверждения того, что оптимизированная реализация сохраняет ожидаемые результаты эталонного алгоритма построения признаков.

Тесты и проверка эквивалентности помогают обнаруживать ошибки реализации и нежелательные изменения значений признаков.

## Ограничения

У текущего эксперимента есть несколько ограничений.

- Оценка проводится на одном временном разбиении данных.
- Эксперименты выполнены на MovieLens 1M, поэтому результаты не обязательно переносятся на другие рекомендательные датасеты.
- Во время тестирования параметры модели остаются неизменными, хотя историческое состояние обновляется по мере поступления взаимодействий.
- Онлайн-протокол предполагает, что оценки предыдущих взаимодействий становятся доступными до формирования последующих предсказаний.
- Взаимодействия с одинаковыми временными метками обрабатываются пакетно и не влияют друг на друга при построении признаков.
- Различия между конфигурациями могут зависеть от конкретного временного разбиения.
- Измерения памяти отражают отслеживаемое пиковое потребление памяти Python и не обязательно охватывают весь объём памяти, используемый процессом.

В дальнейшем можно провести эксперименты на нескольких временных разбиениях, проверить метод на дополнительных датасетах и исследовать устойчивость качества признаков при изменении временного периода.

## Заключение

В проекте исследуется автоматизированное построение исторических признаков для рекомендательных систем и оценивается их влияние на качество бинарного предсказания оценок.

Эксперименты показывают, что использование исторической информации улучшает качество предсказаний по сравнению с базовой конфигурацией.

Среди рассмотренных конфигураций **Rating statistics обеспечивает наилучший ROC-AUC на тестовой выборке — 0.7752**, тогда как конфигурация Combined показывает лучшие результаты на валидации.

Оптимизация построения признаков позволяет ускорить выполнение приблизительно **в 5.15 раза**: время сокращается с 55.53 до 10.77 секунды. Одновременно уменьшается отслеживаемое пиковое потребление памяти Python.

Полученные результаты служат отправной точкой для дальнейшего исследования эффективного построения исторических признаков и временной оценки моделей рекомендательных систем.
